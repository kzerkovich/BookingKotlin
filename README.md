# Учебный проект — Система бронирования билетов на мероприятия
## Описание
Приложение позволяет пользователям искать, бронировать и покупать билеты на различные мероприятия (концерты, спортивные события, театральные постановки и т.д.).
## Технологии

- **Язык**: Kotlin 2.0.0
- **Фреймворки**: Ktor, Exposed
- **База данных**: PostgreSQL + Liquibase для миграций
- **Документация**: OpenAPI 3.0
- **Тестирование**: JUnit 5, Mockito
- **Безопасность**: JWT
- **CI/CD**: GitHub Actions

## Функциональные требования
### Просмотр мероприятий:
- Пользователь может просматривать список мероприятий с фильтрацией по дате, категории и местоположению.
#### Функциональность:
- Получение списка мероприятий через API
- Фильтрация мероприятий по дате, категории и местоположению
- Просмотр детальной информации о мероприятии: название, описание, дата, местоположение, доступные билеты, цена


### Бронирование и покупка билетов:
- Пользователь может бронировать и покупать билеты на мероприятия. На каждое мероприятие может создать не более одного бронирования. В случае, если бронь содержит больше трети от всех билетов, но при этом билеты не были выкуплены, то пользователь получает временный бан на сутки - невозможно будет ни купить, ни забронировать билеты. Пользователь может выкупить все билеты сразу.
#### Функциональность:
- Бронирование билета на мероприятие (Под бронью понимается блокировка билета на 30 минут от других пользователей)
- Покупка билета с использованием платёжной системы
- Просмотр забронированных и купленных билетов
- Отмена бронирования.

### Управление мероприятиями (для администраторов): 
- Администратором является сама платформа. Администраторы могут добавлять, редактировать и удалять мероприятия.
#### Функциональность:
- Добавление нового мероприятия
- Редактирование информации о мероприятии (При переносе мероприятия пользователь получает уведомление)
- Удаление мероприятия (Отмена мероприятия. В данном случае пользователь получает обратно деньги, и уведомление об отмене)
- Управление доступными билетами (количество, цена)



### Нефункциональные требования
#### Производительность:
- Время отклика API, особенно для поиска мероприятий, не должно превышать 100 мс.
- Обеспечить масштабируемость системы для работы с большим количеством запросов и данных.
- Безопасность
- Реализовать аутентификацию пользователей посредством JWT.
- Ограничить доступ к административным функциям.
- Защитить API от распространённых атак (SQL Injection, XSS, CSRF).

#### Поддерживаемость:
- Использование ООП и принципов SOLID.
- База данных, выбор нормальной формы, в которой хранятся данные. Использование системы для миграции данных (Liquibase/Flyway).
- Документированный API (OpenAPI) с подробным описанием эндпоинтов.
- Обязательное покрытие функциональности unit‑тестами и интеграционными тестами.
